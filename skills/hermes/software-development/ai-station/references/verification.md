## Test isolation fixture (avoid writing to repo's real jobs.db / storage/)
Render tests must NOT touch the repo root. Add this fixture to `tests/test_aistation.py`
and apply it to every test that calls `pipeline.enqueue`/`pipeline.submit` or the
`/webhook/n8n` / `/api/jobs` routes (they import `STORAGE_DIR`/`DB_PATH` at module load,
so patch BOTH `config` and `pipeline` globals):
```python
@pytest.fixture
def isolated_state(tmp_path, monkeypatch):
    from src import config, db, pipeline
    work = tmp_path / "state"
    work.mkdir(parents=True, exist_ok=True)
    monkeypatch.setattr(config, "STORAGE_DIR", work)
    monkeypatch.setattr(db, "DB_PATH", work / "jobs.db")
    monkeypatch.setattr(pipeline, "STORAGE_DIR", work)   # critical: pipeline binds it at import
    db.init_db()
    return work
```
Apply with `def test_x(isolated_state):`. Without the `pipeline.STORAGE_DIR` patch the
render still writes into the real repo `storage/`.

## Push + real CI gate (NEVER claim done on local-green alone)
```
git add -A && git commit -q -m "..." && git push
gh workflow run build.yml --ref main        # returns a run URL with id
# poll until completed success:
for i in $(seq 1 35); do
  st=$(gh run view <RUN_ID> --json status,conclusion -q '"\(.status) \(.conclusion)"')
  echo "poll $i: $st"; [ "$(echo $st|grep -o completed)" ] && break; sleep 12
done
```

## What CI actually does (`.github/workflows/build.yml`)
1. `checkout`
2. setup Python 3.11
3. `apt-get install -y ffmpeg fonts-noto-cjk`   ← required for e2e render + CJK captions
4. `pip install -e ".[dev]"`                     ← pulls pyproject `dependencies` + `dev`
5. `pytest`                                       ← all tests incl. real-ffmpeg integration
6. Docker build (+ conditional `docker push` only if `DOCKERHUB_USERNAME` set)

## Recurring CI-only failure
If local passes but CI render `failed`: a runtime import (notably **numpy**)
is missing from `pyproject.toml` `dependencies` — the dev venv had it, the
fresh CI venv did not. Fix: add to `dependencies` AND `requirements.txt`.

## CI robustness decision (build-only, no Docker Hub push)
The Docker buildx/build steps are marked `continue-on-error: true` so a transient
Docker Hub registry timeout (`context deadline exceeded` reaching `registry-1.docker.io`)
cannot turn the whole run red. The pytest step is the gate: **if pytest is green,
CI is green**, even if the image build is skipped/failed. Do NOT add a Docker Hub
token (user decided build-only; keys are never solicited in chat).

## What must go through REAL CI (not local-green alone)
Anything touching: base `dependencies` / `requirements.txt`, `ffmpeg` behavior,
CJK fonts, or the `ThreadPoolExecutor` background path. Local-green is necessary
but not sufficient — always `git push` and poll `gh run view <id>`.
