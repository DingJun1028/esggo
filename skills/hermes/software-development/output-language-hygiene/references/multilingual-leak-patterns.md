# Multilingual leak patterns — observed in this workspace

Class: output hygiene / language consistency  
Related skills: output-language-hygiene (this umbrella), esggo-style (繁體中文優先), hermes-usage-best-practices

本文记錄当前用户环境下曾实际出现过的语言混入模式，供未来会话排查和预防。

## 曾出现的混入类型（2026-08-17）

### 1. 日文粒子混入（Reasoning 段落）
- 粒子：の・に・を・は・が・から・で・て 等
- 句法特征：日语语法主导，技术名词保留英文/中文
- 典型段落：Reasoning 区块整体语感是日语，夹杂中文技术词

### 2. 韩文 morpheme 混入
- 实例片段：`파크한 다음 저리`
- 出現位置：Reasoning 段落中，嵌在日语/中文混合句内
- 特征：短促韩语形态，难以单纯靠字形判断，需逐字元核对

### 3. 简体中文碎片
- 实例：`跑 的`
- 出現位置：Reasoning 段句首
- 特征：与繁体输出上下文冲突，容易被忽略为“同样是中文”

## 根因观察

- 混入发生在 Reasoning 段落（内部推理或中间步骤文本），不限于最终回复
- 模型在处理技术审计/依赖策略等内容时，训练语料中日语/韩语成分被拉入推理链
- 若不在输出前显式检查语言一致性，混入会被保留并发送给用户

## 检测启发式（供复查）

- 扫描候选输出文本，查找：の・に・を・は・が・から・で・て（日）、파크한/다음/저리（韩）、跑/的（简）
- 对无法通过字形确定的短片段，逐字元比对目标语言字符集
- 不只检查“看起来像中文”的段落，也检查 Reasoning / 中间步骤文本

## 处理原则

- 发现混入 → 重写为目标语言（繁体中文），不发送混合文本
- 不以“推理层正常”“上下文污染”为由保留混入
- 若用户指出某段混入，直接定位字元并修正
