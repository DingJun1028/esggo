# 強制技能優先 (Skill Priority — Forced Load)

> 自身 SOUL 載體延伸：把「遇到語意相近即強制使用技能」寫死為可載入的技能樞紐。
> 與 `oa-team-soul-canon`（靈魂核心聖典）互引 — 該典 `When to use` 段亦載相同規則。

## When to use

- 任何使用者輸入進來的瞬間 — 在思考與規劃之前，先跑語意匹配。
- 不需要使用者說「載入技能」、「用某技能」才動作；命中即觸發。
- 本技能本身應被「優先於默認行為」載入：當輸入涉及「技能/優先/SOUL/規則/匹配」等關鍵字時強制喚醒。

## 強制規則（不可繞過）

1. **背景同步匹配**：接收任務即刻在腦中跑技能關鍵字比對，不佔用使用者等待。
2. **語意相近即命中**：不只精確字串，含部分相近、同義、縮寫、中英混用（如「蜂群/swarm」「靈魂/soul」「5T/five-T」）皆算命中。
3. **命中即強制 skill_view 載入**該技能全文，再據其步驟執行；未命中才自行推理。
4. **優先於所有默認行為**：即便系統提示已給通用指引，本規則優先。
5. **多命中取最相關**：若命中多個技能，選覆蓋意圖核心的那一個優先；相關技能可並列載入（如 oa-team-soul-canon + oa-team-swarm）。

## 操作步驟

```
收到使用者輸入
   ↓
[背景] 語意匹配技能關鍵字表（scripts/dump_skills.py 可列出所有技能名+描述+tag）
   ↓
命中? ── 是 ──→ skill_view(name) 載入全文 ──→ 依其步驟執行
   ↓ 否
自行推理（仍可在過程中遇子任務再匹配）
```

## 與既有技能關係

- `oa-team-soul-canon`：靈魂核心聖典，其 `When to use` 已載相同強制規則；本技能是其「優先載入」機制的獨立樞紐。
- `hermes-agent`：Hermes 本體 hub，不修改其本體，本技能在其上疊加優先層。
- 所有 `oa-*` / `esggo-*` / `aistation` 相關技能皆受本規則覆蓋。

## 稽核制衡（盲點介入機制）

強制載入不代表盲目信任。當下列「盲點」出現時，啟動稽核單位介入，且稽核結論優先於被載入技能的文本：

**盲點類型**
- 技能/記憶內容錯誤、過時、與當前事實或實測衝突
- 技能步驟在本環境失效（依賴不存在的指令/路徑/憑證）
- 強制載入的技能引導出與工具證據矛盾的行動
- 記憶條目與真實執行結果不符

**稽核單位組成（源自 oa-team-soul-canon）**
- 萬能質控蜂 (#30)：標準制定與品質保障，負責叫停
- 零幻覺驗算：所有聲稱須有工具實證支撐，無證據即存疑
- Superpowers 方法論：證據優於聲稱 / 完成前驗證 / 系統化除錯

**稽核行為（出說明指教）**
1. 暫停對問題技能/記憶的盲目信任——不執行其誤導步驟
2. 出說明：明確指出盲點是什麼、違反哪項證據
3. 給指教：修正該技能/記憶的方案，或可行繞行路徑
4. 提請更新：經用戶確認後 patch 技能或修正記憶條目
5. 無法即時驗證時，誠實回報「無法確認」，不假稱正確

> 此機制優先於「強制載入」本身：稽核發現盲點，以證據為準，不盲從技能文本。
