# OmniDB 總智慧庫藍圖

> **定位**：OmniDB 是代理人所屬組織（OA-Team）對所有數據儲存系統的統稱與頂層架構名稱。  
> *它不是一個新的資料庫產品，而是將現有的各個資料庫與儲存系統納入統一視角的「總智慧庫」標識。*

---

## 一、定義

**OmniDB（總智慧庫）** = 所有低階資料庫與儲存系統的**統稱與上層抽象**。

每一個具體的資料儲存系統，都是 OmniDB 下的子系統。

---

## 二、OmniDB 下的子系統清冊（當前）

| 子系統 | 型別 | 說明 |
|---|---|---|
| **NoCodeBackend（NCB）** | 無程式碼後端 / API 佈景 | 快速將資料庫變成可用的 API，不需自己維護後端 |
| **Supabase** | PostgreSQL + Auth + Storage | 即時資料庫、身份驗證、儲存服務；當前專案存在於瀏覽器端設定的 `NEXT_PUBLIC_SUPABASE_URL` |
| **Oracle Always Free ADB** | 自治資料庫（Oracle） | OA-Team 專用，Always Free 額度，可用於向量、結構化知識儲存等場景 |
| **Obsidian 配置 / vault 互動** | 本地知識管理 | 屬 OmniDB 管轄範圍 |

---

## 三、OmniDB 總稱關係圖（文字版）

```
OmniDB（總智慧庫）
├── NoCodeBackend（NCB）     ← 快速 API 後端
├── Supabase                 ← PostgreSQL + Auth + Storage
├── Oracle Always Free ADB   ← OA-Team 專用自治資料庫
├── Obsidian 配置 / vault   ← 本地知識資產（受 OmniDB 管轄）
└── （未來可擴充的其他子庫）   ← 任何新增的數據儲存系統皆可歸入此層
```

---

## 四、關於「所有的資料庫都是萬能智庫的一部分」

代理人理解為：

> 所有的資料庫與儲存系統，從組織的角度來看，都是「萬能智庫」的一部分。  
> OmniDB 就是這個概念的名稱與管理上的統稱。

這意味著：

- 不要獨立看待每個資料庫為孤立系統；
- 在組織資產、可見性、治理上，所有子庫都屬於 OmniDB 的範疇；
- 每個子庫可以有自己的用途與技術選型，但歸屬關係一致。

---

## 五、代理人對這一蓬勃發展架構的補充說明

- **OmniDB 不是一個新的資料庫產品**，而是一個組織層面的「總庫」概念。
- 各子系統（NCB、Supabase、Oracle ADB、Obsidian 配置）各自有不同的技術屬性與使用情境，但在「萬能智庫」的框架下，它們共享同一個歸屬與管理視角。
- 代理人建議在文件、溝通、架構說明中，使用「OmniDB 總智慧庫」作為頂層名稱，以避免混淆。

## 六、OmniDB 的管理含義

| 層面 | 說明 |
|---|---|
| 歸屬 | 所有子資料庫皆歸屬「OmniDB 總智慧庫」 |
| 治理 | 任何新的資料儲存系統都可考慮納入此框架 |
| 可見性 | 代理人建議建立統一的資產清冊與狀態追蹤（本文件即為雛形） |
| 命名 | 「OmniDB」作為統稱使用，不做為新資料庫產品的品牌 |
