# ADR 003: Zero-Blank UX Strategy (無空白頁使用者體驗與版型優先策略)

## 狀態 (Status)
**已接受 (Accepted)**
日期：2026-06-20

## 背景 (Context)
在 ESG 永續報告的編撰過程中（SustainWrite 模組），使用者經常會遇到「缺乏實證數據 (Vault 內無資料)」的狀況。若系統此時回傳「資料缺漏」或是「留白」，將導致使用者感到無助、不知道該如何下手，進而提高系統的進入門檻與使用者的認知負擔。

根據「服務即教學」與「無作妙德（自發治理與無縫顯化）」的系統精神，我們需要確保系統即使在資料匱乏的狀態下，也能引導使用者完成工作。

## 決策 (Decision)
我們採用 **Zero-Blank UX Strategy (零空白體驗策略)**，並在 AI 擴寫與全息編織的 Prompt 中加入強制的系統指令：
1. **永遠提供版型或答案選項**：當 AI 發現給定的指標狀態為「尚未連結數據」時，禁止留空或僅回覆缺漏警告。
2. **自動生成最佳實踐範本**：AI 必須主動根據產業標準，撰寫出符合 GRI 準則與正式報告語氣的「預設內容」或「常見答案選項」。
3. **將「從零撰寫」轉化為「填空與選擇」**：確保使用者總是有一個具體的結構可以參考、修改或填空，大幅降低「白紙恐懼症」。

### 實作細節
在 `app/sustain-write/page.tsx` 中，我們針對 `expandContentWithAI` 的 `prompt` 進行了修改，注入以下系統指令：
> **重要指示：如果發現有「尚未連結數據」的指標，請自動為使用者撰寫符合產業標準的「預設內容、最佳實踐範本或常見答案選項」，讓使用者有明確的版型可以參考修改，絕不要留白或僅提示缺漏。**

此外，我們在 `SustainWrite` 的藍圖視圖中，實作了 **「永續撰寫單據需求一覽表」**，將抽象的指標代碼具象化為文件需求，並在章節卡片中明確標示「待收齊單據」，兼顧了「5T - Tangible (可感知)」與「5T - Trackable (可追蹤)」的要求。

## 後果 (Consequences)

### 正面影響 (Positive)
* **大幅降低認知負擔**：使用者不再面對空白頁，可以直接對現有優質範本進行修改。
* **縮短報告產出時間**：企業可先根據範本勾勒出報告雛形，後續再由專人慢慢補齊 Vault 數據，將原先必須序列化的流程（先收齊資料 -> 再撰寫）轉變為可平行的流程（邊撰寫 -> 邊收齊資料）。
* **符合「服務即教學」**：透過系統生成的最佳實踐範本，無經驗的使用者也能直接學習到產業內的標準寫法。

### 負面影響 / 挑戰 (Negative / Risks)
* **幻覺風險**：如果 AI 產生的範本過於肯定或編造虛假數據，使用者可能誤用。因此，必須在系統層面加上標籤或防護網（例如 5T Hash Lock 未 verified 前不可發布），確保使用者知道這些是「範本」而非「實證資料」。
