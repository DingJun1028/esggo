**關鍵不變式**
- 單一真相源：名冊/契約手寫一次，配對/觸達由 derive 函式程式化派生（杜絕枚舉漂移）
- 雙向同步：generator 再生 consumer `.d.ts`，CI 每跑重生
- 5T 同一套守門：統一閘 `verify-terminal-origin.mjs` 只聚合子閘 exit code，**任一子矩陣紅燈即整體紅燈**

## 四、統一驗證閘（Unified Gate）

## 六、實戰踩坑（已固化技能書 `oa-gap-matrix-terminal-origin`）

1. **pnpm run 卡 postinstall**：直跑底層命令（`node … && npx tsx …`）繞過
2. **readonly 推導 TS4104**：`ReadonlyArray<readonly [..]>` 不能指派可變 → 改 `ReadonlyArray<[..]>`
3. **web_extract 吞 TS generics**：比對 canonical/consumer 用 browser raw 抓源
4. **閘 exit code 誤判**：`$?` 前勿接 `| tail`/`head`；MSYS `>nul` 誤生空檔 `nul` → 用 `>/dev/null 2>&1`
5. **分支異常**：`git stash pop` 後 cwd 可能不在 main → commit 前 `git branch --show-current`；落錯 `git cherry-pick` 回 main
6. **git index 鎖**：他人 WIP 卡 stash（`could not write index`）→ 勿強行 rebase/push，先只 commit 本輪檔
7. **consumer 閘斷言範圍**：只驗該 consumer 實際消費的契約（LC 不含 Float，多驗假紅燈）
8. **oa-swarm 路徑脆弱**：`SRC = ROOT/../../esggo/shared` 改 `path.resolve(ROOT,'..','shared')`

## 七、誠實缺口與決策紀錄

- 多次 push 遇 origin/main 被他人並行推進 → 採 `fetch + stash(他人WIP) + rebase + 復測綠 + pop + push`，從未吞他人工作
- GitHub dependabot 73 漏洞為 repo 全域既有資訊，非本倡議引入
- CI parallel 化僅改 YAML（lint 通過），實跑需 push 後 GitHub Actions 驗證；本地統一閘已確認五路綠
