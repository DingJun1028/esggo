⚡ Bolt: [performance improvement] Optimize list item rendering and fix Cloudflare Worker build

💡 What:
1. Wrapped functional components `ReportItemCard` (in `app/daily/page.tsx`), `BarChart`, and `Sparkline` (in `app/sonnar/page.tsx`) with `React.memo()`.
2. Fixed Cloudflare Worker build failure by explicitly pointing `wrangler.toml`'s `main` to the compiled output `my-worker/dist/index.js` (instead of the TypeScript source `my-worker/src/index.ts` which Cloudflare workers CI might reject if not properly configured for TypeScript directly), adding a `[build]` command block, removing deprecated `logpush = true`, and tracking `my-worker/dist/.gitkeep` to bypass gitignore on checkout.

🎯 Why:
1. These components act as leaf nodes or list items that are rendered multiple times in lists or grids. Without memoization, they would re-render needlessly when parent components (`DailyReportPage` and `SonnarDashboard`) re-render due to unrelated state updates (e.g. filter changes, incoming WS data), causing redundant layout calculations and DOM diffing.
2. The Cloudflare Workers CI environment failed because the assets directory `dist` was gitignored and not generated on the fly, and paths were not correctly rooted into the workspace subfolder. Also, `src/index.ts` is not compiled out-of-the-box by the default wrangler setup on Cloudflare without custom builds.

📊 Impact:
Significantly reduces unnecessary React render cycles when the overarching dashboards update their status/reports state. Unblocks Cloudflare Worker deployments.

🔬 Measurement:
Run the app in dev mode and use React DevTools Profiler while toggling regions or severity levels; the memoized components will bypass re-rendering if their props are unchanged. CI will pass for Workers Builds.
