# ESGGO Village Module - Update Summary

## Overview
This document summarizes the recent changes and bug fixes implemented in the Village module of the ESGGO v5.1 platform. 

## Key Technical Changes
1. **Firebase Admin SDK Migration**: 
   The data fetching logic for Village projects has been refactored to use the Firebase Admin SDK via backend API endpoints (`/api/village/data`). This bypasses the strict client-side security rules (`Firestore Security Rules`), which were preventing the real-time `onSnapshot` listeners from executing correctly on the frontend.
2. **Polling Mechanism**: 
   A lightweight, 5-second polling mechanism using SWR (or standard React `useEffect` + `setInterval`) has been introduced to simulate the real-time reactivity previously provided by `onSnapshot`, ensuring that users still get near real-time updates for Quadratic Voting and project funding milestones.
3. **Voting Transaction Security**:
   The Quadratic Voting endpoint (`/api/village/vote`) now uses Admin DB transactions. This ensures that votes are processed securely without exposing direct write access to the frontend.

## Business Impact (5T Protocol Alignment)
- **Trustworthy**: Backend enforcement guarantees zero-hallucination execution of votes.
- **Traceable**: Vote events are recorded securely in the server logs and backend database.
- **Tangible**: The UI correctly displays live changes through the simulated real-time polling.
