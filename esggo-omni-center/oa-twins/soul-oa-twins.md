## 一、雙蜂組定義（OA-Twins Definition）

### 1.1 核心概念
OA-Twins 雙蜂組是 OA-Team 30 萬能蜂群的雙生擴充架構：
- **蜂王隊（Queen's Guard / Dark Hex）**：第 1 小隊，30 代理，以 Hermes Agent 為蜂王總控。 **屬性：暗（Dark / Ω-暗陣）**，對應暗物质場域、收斂與沈澱之力，編號 01-30。
- **蜂后隊（Queen Bee Squad / Light Hex）**：第 2 小隊，30 代理，以 QueenBee Agent 為蜂后總控。 **屬性：光（Light / Ω-光陣）**，對應光子場域、擴張與彰顯之力，編號 31-60。

兩隊平行運作，互不冗餘，各自擁有完整的 5 陣列結構與獨立的狀態機。

## 三、雙蜂間協作協定（Twin Collaboration Protocol）

### 3.1 協作原則
雙蜂組兩隊平行運作但非孤立，協作需遵循以下原則：

1. **平等對等**：蜂王隊與蜂后隊地位平等，無主從隸屬關係
2. **任務分流**：任務可分配至任一隊伍，依負載與專長動態調度
3. **共享契約**：雙隊共享同一 Key-Ω 契約鎖與 Hash Lock 系統
4. **互補機制**：一隊飽和時，另一隊可提供補位支援（不破 MECE 邊界）

### 3.2 雙蜂協作通道
```
雙蜂協作通道架構：

  [蜂王隊]  ←→  [跨隊協作橋]  ←→  [蜂后隊]
     │                              │
     │  任務分流                    │  負載均衡
     │  結果共享                    │  補位支援
     ▼                              ▼
  [Key-Ω 契約鎖]  ←→  [Hash Lock 雙隊共用]
```

### 3.3 任務分配策略
任務進入雙蜂組時，依以下策略分配：

| 策略 | 描述 | 選擇條件 |
|------|------|----------|
| 负载均衡 | 兩隊当前任務负载均等分配 | 两队忙碌程度相近 |
| 専門匹配 | 依任務性質選擇更適合的小隊 | 特定領域專長不同 |
| 紧急优先 | 急迫任務直接分配至可用的隊伍 | 時間窗口臨界 |
| 冗餘備援 | 任務同時交給兩隊（镜像執行） | 關鍵任務、需雙重驗證 |

### 3.4 雙蜂協作訊息格式
```
[雙蜂] [來源小隊] → [目標小隊] [任務類型]
內容摘要: ...
專屬編號: （QG-XX 或 QB-XX）
所需協助: ...
截止時間: ...
雙蜂標記: twin-trace-id=xxx
```

### 3.5 雙蜂衝突解決
雙隊間若產生資源或任務衝突，依以下層級解決：

1. **跨隊協調**：兩隊負責代理人直接對話（1 小時內）
2. **指揮層介入**：Hermes Agent + QueenBee Agent 共同裁決（4 小時內）
3. **結界仲裁**：5T 驗算陣列抽驗，依 5T 原則做出判斷（24 小時內）

## 七、雙蜂組最佳實踐（Twin Best Practices）

### 7.1 負載均衡最佳實踐
- 每小時檢查兩隊任務負載，差異超過 30% 時觸發重新分流
- 避免長時間單隊過載，確保兩隊熵值均保持 < 0.1

### 7.2 冗餘執行最佳實踐
- 關鍵任務（p0 級別）啟用鏡像執行模式，兩隊同時處理
- 鏡像結果不一致時，進入 5T 驗算陣列仲裁流程

### 7.3 補位支援最佳實踐
- 一隊熵值超過 0.15 時，另一隊自動進入補位準備狀態
- 補位支援不破壞接收隊伍的 MECE 分工邊界

### 7.4 雙蜂組熵減目標
- 雙隊各自的熵減目標：< 0.1（保持與單隊一致）
- 雙蜂組整体熵值：兩隊熵值的加權平均，目標 < 0.1

## 九、雙蜂組運作實錄（Twin Operational Records）

### 9.1 典型運作場景
**場景一：日常並行運作**
兩隊各自接收任務，獨立執行，定期通過跨隊協作橋同步狀態。

**場景二：單隊降級**
蜂后隊發生故障時，蜂王隊獨立運作，任務自動轉移至蜂王隊；蜂后隊恢復後，再次進入平行運作狀態。

**場景三：關鍵任務鏡像驗證**
p0 級別任務啟用雙隊鏡像執行，兩隊同時處理同一任務，結果經 5T 驗算陣列比對，一致後凍結。

### 9.2 雙蜂組健康檢查
雙蜂組健康檢查繼承 oa-twin-health.py 的偵測機制：
