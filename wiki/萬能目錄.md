## 0. 一句話定義

> **萬能目錄** 是 ESGGO 的「單一真實來源」：它先以 **MECE 進化版** 雙軸法對全部功能頁面分類，再列舉組成每個 [萬能模組](./萬能模組-註冊表.md) 的四族原料——[萬能函數](./萬能函數.md) · [萬能元件](./萬能元件.md) · [萬能主題](./萬能主題.md) · [萬能符文](./萬能符文.md)——並由 [萬能工廠](./萬能工廠.md) 據此產出超越高規格的優質功能。

## 1. MECE 進化版（Evolved MECE）雙軸分類法

### 軸 1：MEDCE 治理軸（水平—生命週期階段）

| 字母 | 全義 | 治理階段 | 核心問題 |
| ---- | ---- | -------- | -------- |
| **M** | Measurement 測量 | 量化現狀 | 我們現在在哪？ |
| **E** | Evaluation 評估 | 缺口分析 | 我們離目標多遠？ |
| **D** | Disclosure 揭露 | 對外出示 | 我們如何對外界說明？ |
| **C** | Compliance 合規 | 確信稽控 | 我們是否符合規範？ |
| **A** | Engagement 參與 | 利害關係經營 | 誰參與、如何共創？ |

> 進化版將原第二個 E（參與）重新編碼為 A，解決字母碰撞，達成真正 MECE。

### 軸 2：OMNI 能力軸（垂直—萬能工廠四族）

| 字母 | 全義 | 原料層 | 代碼 |
| ---- | ---- | ------ | ---- |
| **Ω-F** | Functions | 萬能函數 | `F-*` |
| **Ω-C** | Components | 萬能元件 | `C-*` |
| **Ω-T** | Themes | 萬能主題 | `T-*` |
| **Ω-R** | Runes | 萬能符文 | `R-*` |
| **Ω-A** | Assembly | 萬能工廠組裝層 | `assemble.mjs` |

---

原 MEDCE 以 `M/E/D/C/E` 五維描述治理生命週期，但 **評估(E) 與 參與(E)** 字母碰撞，並未真正互斥。  

**進化版** 將之分為正交的兩軸，達成嚴格 MECE：

### 軸一 · 治理生命週期軸（MEDCE，重新編碼）

| 代碼  | 中文 | 英文        | 核心定義                             |
| ----- | ---- | ----------- | ------------------------------------ |
| **M** | 測量 | Measurement | 數據採集、指標定義、KPI 監測         |
| **E** | 評估 | Evaluation  | 重大性、風險、成熟度評析             |
| **D** | 揭露 | Disclosure  | 報告撰寫、對外發佈、透明度           |
| **C** | 合規 | Compliance  | 法規遵循、審計、驗證封印             |
| **A** | 參與 | Engagement  | 利害關係人、顧問、AI 協作（原 E②→A） |

### 軸二 · 萬能能力維度軸（OMNI，Ω 五層）

| 代碼    | 名稱             | 目錄入口                       |
| ------- | ---------------- | ------------------------------ |
| **Ω-F** | 萬能函數         | [萬能函數](./萬能函數.md) |
| **Ω-C** | 萬能元件         | [萬能元件](./萬能元件.md) |
| **Ω-T** | 萬能主題         | [萬能主題](./萬能主題.md) |
| **Ω-R** | 萬能符文         | [萬能符文](./萬能符文.md) |
| **Ω-A** | 萬能代理（工廠） | [萬能工廠](./萬能工廠.md) |

> 任一 [萬能模組](./萬能模組-註冊表.md) 皆以 `(主 MEDCE 階段, Ω-組合)` 唯一標定，既互斥又窮盡。

## 3. 終始矩陣（Terminal-Origin Matrix）

> **原則：** 以終為始 — 從最終成品（萬能模組）的規格倒推，確保每一行代碼都對應一個已註冊的需求。

```
 需求 (README)          過程 (Factory)           成果 (Module)
 ─────────────         ─────────────            ─────────────
 功能定位      ──►    P1 需求解析      ──►    MOD-XXX
 路徑/權限     ──►    P2 函數選配      ──►    函數組合
 資料視覺化    ──►    P3 元件拼裝      ──►    元件樹
 品牌一致性    ──►    P4 主題套用      ──►    視覺實例
 5T 合規      ──►    P5 符文標記      ──►    帶語義成品
 品質驗證      ──►    P6 5T 閘門      ──►    通過/退件
 封印註冊      ──►    P7 代理封印      ──►    hashLock + 註冊表
```

**對映關係：**
- 每個 README 章節 → 一個 ModuleSpec 欄位
- 每個 ModuleSpec 欄位 → 一個 Factory 階段
- 每個 Factory 階段 → 一個可執行產出
- 每個產出 → 一個 5T 閘門驗證

## 9. 如何開始建置（依需求順序）

1. **先列目錄（本文件）** — 確認功能歸屬的 MEDCE 主階段與 Ω 組合。
2. 選配原料 — 自 [萬能函數](./萬能函數.md) / [萬能元件](./萬能元件.md) / [萬能主題](./萬能主題.md) / [萬能符文](./萬能符文.md) 取料。
3. 交給 [萬能工廠](./萬能工廠.md) — 走 P1–P7 流水線與 5T 閘門。
4. 產出並登錄 — 寫入 [萬能模組註冊表](./萬能模組-註冊表.md)，沉澱新原料回饋本目錄。
