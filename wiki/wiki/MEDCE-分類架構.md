## 什麼是 MEDCE？

**MEDCE** 是 ESGGO 平台採用的五大功能分類維度，對應 ESG 治理生命週期的核心五大能力域：

| 代碼  | 中文名稱 | 英文名稱        | 核心定義                                                  | 對應治理階段 |
| ----- | -------- | --------------- | --------------------------------------------------------- | ------------ |
| **M** | **測量** | **Measurement** | 數據採集、指標定義、KPI 監測、基線建立                    | **量化基礎** |
| **E** | **評估** | **Evaluation**  | 雙重重大性分析、基準比對、風險評分、策略評析              | **質化分析** |
| **D** | **揭露** | **Disclosure**  | 報告撰寫、對外發佈、利害關係人溝通、透明度建構            | **對外輸出** |
| **C** | **合規** | **Compliance**  | 法規遵循、審計追蹤、驗證封印、標準對齊、內控管理          | **信任保證** |
| **E** | **參與** | **Engagement**  | 利害關係人對話、顧問協作、AI 智能協作、教育培力、任務協同 | **生態共創** |

> **設計原則**：每個功能頁面可具備**單一主分類**與**多重輔助分類**，反映真實業務場景的複合性。

## 分類應用指南

### 1. 新功能開發時的分類原則

```
Step 1: 識別功能核心目的 → 決定主分類
Step 2: 分析功能涉及的治理環節 → 標記輔助分類
Step 3: 對照既有分類分布 → 確保架構平衡
Step 4: 更新本文件與 Wiki 索引
```

### 2. 分類衝突解決機制

| 情境                            | 原則                                                           |
| ------------------------------- | -------------------------------------------------------------- |
| 功能同時屬於 M 和 E             | 以「輸出產出」判斷：產出指標數據 → M；產出分析報告 → E         |
| 功能同時屬於 C 和 D             | 以「信任層級」判斷：面向監管/審計 → C；面向大眾/利害關係人 → D |
| 功能同時屬於 E(評估) 和 E(參與) | 以「互動對象」判斷：對議題/數據 → 評估；對人/組織 → 參與       |

### 3. 跨分類整合場景

| 整合場景       | 涉及分類      | 範例頁面                                         |
| -------------- | ------------- | ------------------------------------------------ |
| **報告全流程** | M → E → D → C | SustainWrite + Vault + Publish                   |
| **淨零管理**   | M → E → D → E | Environmental → Roadmap → Finance → Stakeholders |
| **供應鏈治理** | M → E → C → E | Supply-Chain → Templates → Audit-Log → Advisors  |
| **知識資產化** | M → E → D → E | Digital-Twin → Library → Reading-Room → Academy  |
