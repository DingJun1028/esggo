# 萬能工廠 OmniFactory

[Ω-A | 萬能能力維度 · 代理組裝層]

> **所屬體系：** 萬能系統（Omni System）  
> **上層目錄：** [萬能目錄](../萬能目錄.md)  
> **定義：** 萬能工廠是將 [萬能函數](./萬能函數.md) · [萬能元件](./萬能元件.md) · [萬能主題](./萬能主題.md) · [萬能符文](./萬能符文.md) 四族原料，依 [萬能目錄](../萬能目錄.md) 的 MECE 進化版分類，自動組裝出「超越高規格」[萬能模組](./萬能模組-註冊表.md) 的生產系統。

---

## 1. 工廠定位

```
原料層（Ω 四族）           組裝層（Ω-A）              產出層
─────────────────        ─────────────────        ───────────────
Ω-F 萬能函數  ─┐
Ω-C 萬能元件  ─┤──►  [萬能工廠 OmniFactory]  ──►  萬能模組（功能頁）
Ω-T 萬能主題  ─┤        5T 品質閘門              WIKI 式設計規格
Ω-R 萬能符文  ─┘
```

工廠由 `OmniAgent`（`lib/omni-agent`）驅動，支援 `autonomous / supervised / debug` 三種模式。

---

## 2. 生產流水線（Pipeline）

| 階段 | 名稱     | 輸入                  | 處理                                       | 輸出                  |
| ---- | -------- | --------------------- | ------------------------------------------ | --------------------- |
| P1   | 需求解析 | 功能規格 / MEDCE 標籤 | 對照 [萬能目錄](../萬能目錄.md) 判定主分類 | 模組契約 `ModuleSpec` |
| P2   | 函數選配 | `ModuleSpec`          | 自 [萬能函數](./萬能函數.md) 選取 `F-*`    | 函數組合              |
| P3   | 元件拼裝 | 函數組合              | 自 [萬能元件](./萬能元件.md) 選取 `C-*`    | 元件樹                |
| P4   | 主題套用 | 元件樹                | 套用 [萬能主題](./萬能主題.md) 變體        | 視覺實例              |
| P5   | 符文標記 | 視覺實例              | 疊加 [萬能符文](./萬能符文.md) `R-*`       | 帶語義實例            |
| P6   | 5T 閘門  | 帶語義實例            | 五維驗證（真善美信通）                     | 通過 / 退件           |
| P7   | 代理封印 | 通過實例              | `executeAssembly` + `hashLock`             | 萬能模組成品          |

---

## 3. 品質閘門（5T Quality Gate）

模組僅在 P6 全數通過方可產出：

| 閘門  | 檢查點               | 退件條件 |
| ----- | -------------------- | -------- |
| T1 真 | 數值 / 單位 / 時間戳 | 任一缺失 |
| T2 善 | 來源標記             | 無來源   |
| T3 美 | 稽核軌跡             | 無軌跡   |
| T4 信 | `hash_lock`          | 可被篡改 |
| T5 通 | 第三方可驗算         | 無法驗算 |

> 對應 [萬能函數](./萬能函數.md) `F-5T` 族群。

## 4. 工廠輸入／輸出契約

```ts
interface ModuleSpec {
  id: string; // 模組 ID，如 MOD-DASHBOARD
  medce: { primary: 'M' | 'E' | 'D' | 'C' | 'A'; aux: string[] };
  functions: string[]; // 引用的 F-* 函數
  components: string[]; // 引用的 C-* 元件
  theme: string; // 主題變體
  runes: string[]; // 疊加的 R-* 符文
}

interface ModuleArtifact {
  spec: ModuleSpec;
  wiki: string; // WIKI 式功能頁設計文件
  hashLock: string; // 5T 固化憑證
}
```

## 5. 實作範例：從 0 組裝「控制台」模組

1. **P1** 需求：平台總覽 → `medce.primary = M`，輔助 `E, D`。
2. **P2** 選函數：`aggregateKpi` + `getAgentStatus`。
3. **P3** 選元件：`BrandKpiCard`(×N) + `StandardPage` + `BrandT5Strip`。
4. **P4** 套主題：`solid-card-default`，強調卡用 `solid-card-highlight`。
5. **P5** 標符文：`R-MEDCE ▣` + `R-5T` 全五符 + `R-STATE ●`。
6. **P6** 5T 通過（KPI 有值/來源/軌跡/hash/可驗）。
7. **P7** `executeAssembly` → 產出 `MOD-DASHBOARD`，寫入 [萬能模組註冊表](./萬能模組-註冊表.md)。

---

## 6. 工廠治理原則

1. **不可繞過閘門**：未過 5T 的模組不得進入發佈。
2. **單一真實來源**：四族原料僅能取自對應目錄，禁止頁面私有副本。
3. **可溯可驗**：每個成品攜 `hashLock`，對應 `R-SEAL` 符文。
4. **進化即回饋**：新模組沉澱的新函數/元件須回寫 [萬能目錄](../萬能目錄.md)。
