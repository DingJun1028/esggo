# 🏛️ ESGss InfoOne 最佳實踐工作流 (Best Practice Flow v1.0)

> **核心宗旨**：「卓越即標準，零幻覺即真理。」——本工作流整合了 5T 協議、Deep Design Thinking 與 Purple Ban 禁令，確保每一次開發都是一次系統的升維。

---

## 🌀 第一階段：覺察與規劃 (Awareness & Planning)

在開始任何代碼編寫前，必須執行以下「靈魂審訊」：

1. **Modular Skill Loading Protocol**:
   - ✅ 讀取 `GEMINI.md` 首選規則。
   - ✅ 讀取對應領域 Agent (如 `frontend-specialist.md`)。
   - ✅ 載入 `OMNISKILL_BOOK.md` 中的 5T 驗算標準。

2. **Deep Design Thinking (前端必備)**:
   - **Cliché Scan**: 是否使用了 Bento Grid、左文右圖、或過度圓角？如果是，請 **BETRAY IT**。
   - **Topological Betrayal**: 挑戰用戶對頁面佈局的記憶慣性。
   - **Purple Ban**: 嚴禁使用紫色/靛紫色系。優先使用 Aqua 青 (#63a6b0) 與永恆金 (#ffd700)。

3. **5T 預演**:
   - 此功能產出的數據是否 **Tangible (可感知)**？
   - 是否具備 **Traceable (可溯源)** 的 UUID 與 Timestamp？

---

## 🛠️ 第二階段：實作與轉化 (Execution & Transformation)

1. **Clean Code Protocol**:
   - 使用 TypeScript 嚴格模式。
   - 移除所有 `any` 型別，改用精確的 `IComponentCore` 或業務介面。
   - 函數命名語法：`[Action][Target][Context]` (例: `manifestReportAtom`)。

2. **Aesthetic Implementation**:
   - **LiquidGlass**: 所有的容器必須具備液態玻璃質感，背景建議使用 `var(--theme-surface)` 固態玻璃以防止破圖。
   - **Ghost-Free Layout**: 確保在亮色模式下，文字與背景具備 4.5:1 以上的對比度。

3. **Karma Repair (果因修復)**:
   - 遇到 Bug 時，啟動 **Jules 九步驟協議**：觀果 ➜ 立願 ➜ 尋因 ➜ 修因 ➜ 造緣 ➜ 結果 ➜ 驗因 ➜ 證果 ➜ 傳法。

---

## 🔍 第三階段：審核與封印 (Audit & Sealing)

1. **Maestro Auditor (最後門神)**:
   - **The Template Test**: 「這看起來像 Vercel 模板嗎？」如果像，請重寫佈局。
   - **The Memory Test**: 用戶明天還會記得這個設計嗎？
   - **Purple Check**: 再次確認沒有誤用紫色。

2. **Validation Loop**:
   - `npm run lint`: 確保語法與規範通過。
   - `npx tsc --noEmit`: 確保型別鏈路完全閉環。

3. **5T Sealing (封印)**:
   - 確保數據產出時，已賦予 `hash_lock`。
   - 更新 `task.md` 並產出 `walkthrough.md` 顯化成果。

---

## 🏁 終極檢查清單 (Final Checklist)

- [ ] **Purple Ban**: 是否 100% 移除紫色？
- [ ] **Type Healing**: 是否 100% 移除 `any`？
- [ ] **5T Compliance**: 數據是否具備溯源屬性？
- [ ] **Aesthetic Wow**: 畫面是否能讓用戶感到驚艷？
