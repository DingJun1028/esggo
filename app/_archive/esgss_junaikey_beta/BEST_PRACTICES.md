## 容器化最佳實踐（Dockerfile Integration）

採用 **多階段建構（Multi-Stage Build）** 策略，確保生產環境映像檔最小化。

### 協議要求

| 要求 | 說明 |
| :--- | :--- |
| **基礎映像選擇** | 禁止使用 `node:20-alpine` 作為生產環境，改用 `nginx:1.25-alpine` 作為最終階段 |
| **類型安全丟棄** | 開發階段完成後，僅保留 `nginx` 靜態檔案 |
| **安全掃描** | 每次建構前執行安全掃描 |

## 前端架構準則（Nginx Tuning）

`nginx.conf` 需針對 Cloud Run 環境優化，確保回應速度與安全性。

### 優化項目

- **安全標頭設置**：必須包含 CSP, X-Frame-Options 等
- **Gzip 壓縮**：啟用所有文字類型
- **SPA 路由**：正確處理 React Router 404 問題

---

## 後端架構準則（React + TypeScript）

遵循 **關注點分離（Separation of Concerns）** 原則：

| 層級 | 職責 |
| :--- | :--- |
| **UI 元件** | 僅負責渲染與使用者互動 |
| **數據層** | 處理 API 請求與狀態管理 |

### 類型安全定義

- **禁止 `any`**：所有參數必須明確定義類型
- **唯讀保護**：數據模型必須使用 `readonly` 或 `Object.freeze()`

## 信任驗證機制（5T Protocol: 4T+1）

系統必須確保所有數據符合以下定義：

| 驗證 | 實作 | 說明 |
| :--- | :--- | :--- |
| **Traceable** | 可溯源 | 數據必須有來源標記 |
| **Trackable** | 可追蹤 | 需記錄數據流動路徑 |
| **Transparent** | 可透明驗算 | 設計協議需公開可驗證 |
| **Tangible** | 可感知 | 抽象指標需轉換為具體 UI |
| **Trustworthy** | 不可篡改 | 最終狀態由 ZKP 鎖定 |

## 文件更新規範（v7.0.0 Sentient Standard）

### 6.1 文件編碼規範

- 所有 Markdown 文件必須使用 **UTF-8 無 BOM** 編碼
- 禁止使用舊式編碼 `BIG5` 或其他地區編碼

### 6.2 類型安全工作流程

開發者在提交前必須執行以下驗證：

```bash
1. git fetch origin          # 獲取最新狀態
2. git rebase origin/main    # 變基到主分支
3. npm run build             # 建構驗證
4. git push origin main      # 推送
```
