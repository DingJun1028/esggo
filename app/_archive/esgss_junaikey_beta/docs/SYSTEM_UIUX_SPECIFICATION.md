## 一、設計系統概述

### 1.1 設計哲學

本設計系統以「上善若水」為核心視覺理念，追求如水般清澈、流動、和諧的視覺體驗。系統採用便當盒式（Bento Grid）佈局，將複雜的 ESG 知識資訊以模組化、區塊化的方式呈現，讓學習者能夠在有限的螢幕空間內獲取最大量的相關知識。整體設計強調「服務即教學」的概念，每一個 UI 組件、每一個互動細節都承載著知識傳授的功能，讓使用者在操作系統的過程中自然地吸收 ESG 相關知識。

設計系統遵循三大核心原則：第一是「資訊密度最大化」，在保持視覺整潔的前提下，尽可能在同一螢幕區域內呈現更多相關資訊；第二是「視覺層級清晰化」，透過色彩、大小、位置等視覺線索建立明確的資訊優先順序；第三是「互動體驗一致化」，確保所有頁面、所有功能模組都遵循相同的互動模式，降低使用者的學習成本。

### 1.2 設計系統組成

本設計系統由七大核心模組組成，各模組之間相互協作、層層疊加，共同構成完整的視覺語言體系。第一模組為「主題風格規範」，定義色彩系統、字體系統與整體視覺調性；第二模組為「排版設計規格」，建立便當盒式佈局哲學、網格系統與間距規範；第三模組為「組件設計規範」，詳細規定各類 UI 元件的視覺樣式與互動行為；第四模組為「響應式設計」，定義不同裝置尺寸下的佈局變化規則；第五模組為「多語系規範」，確保系統能夠支援繁體中文、英文、日文、韓文等多種語言；第六模組為「動畫規範」，建立有意義的動效語言；第七模組為「無障礙規範」，確保系統符合 WCAG 2.1 AA 級標準。

設計系統採用「上善若水」作為預設主題，主題色 #63A2B0 取自清澈溪流的青藍色調，象徵 ESG 環境永續的核心價值。此色彩系統不僅提供視覺上的愉悅感受，更透過色彩的象徵意義強化使用者的環保意識，體現「服務即教學」的核心理念。

色彩系統採用 HSL 色值體系進行管理，方便進行明度、彩度的調整以產生變化色。Primary 色系以 #63A2B0 為核心色，展開為淺色變化與深色變化，形成完整的九宮格色彩矩陣。Secondary 色系選用暖橙色系，與 Primary 色系形成互補關係，用於強調重要動作與吸引注意。Functional 色系則依據功能屬性分為成功、警告、錯誤、資訊四種類型，確保使用者能夠快速識別系統狀態。Neutral 色系提供灰階色彩，用於文字、邊框、背景等基礎視覺元素。

## 三、排版設計規格

### 3.1 便當盒式佈局哲學

便當盒式佈局（Bento Grid Layout）是本系統的核心排版理念，源自日式便當盒的分格設計概念，將不同類型的內容放置在獨立且整齊的「便當盒」區塊中，每個區塊承載特定的功能或資訊，彼此之間既有分隔又相互關聯。此佈局方式的優勢在於：模組化設計便於組裝與維護；資訊密度高且視覺整潔；各區塊可獨立響應式調整；使用者在掃描頁面時能快速定位目標資訊。

便當盒的設計遵循「完整單一」原則，每個便當盒應該是一個自給自足的資訊單元，包含標題、內容與可能的操作區域。使用者應該能夠在不離開便當盒的情況下獲取完整的資訊或完成基本的操作。若便當盒內容過於複雜，應考慮拆分為多個便當盒，或使用展開收合機制管理資訊層級。

便當盒之間的間距統一為 16px 或 24px 的倍數，確保視覺上的整齊與呼吸空間。便當盒內部的內容間距則統一為 8px 的倍數，建立一致的視覺節奏。便當盒的圓角標準為 8px 或 12px，視便當盒的大小與重要性而定——較大的便當盒使用較大的圓角，營造柔和的視覺效果。

### 3.2 網格系統

本系統採用 12 欄網格系統作為基礎佈局框架，欄位間距（gutter）設定為 24px，頁面左右邊距根據裝置尺寸動態調整。網格系統配合便當盒式佈局使用，便當盒可跨越 1 到 12 欄的寬度，具體寬度根據內容重要性與資訊密度決定。

12 欄網格的基本計算公式如下：欄位寬度 =（容器寬度 - 11 × 欄位間距）÷ 12。對於常見的桌面顯示器寬度 1440px，單一欄位寬度約為 100px，6 欄便當盒寬度約為 624px，4 欄便當盒寬度約為 408px，3 欄便當盒寬度約為 300px。此計算方式確保便當盒在不同容器寬度下都能保持整齊的排列。

便當盒寬度的常用對應關係如下：1 欄便當盒適用於小型資訊卡，寬度佔比約 8%；2 欄便當盒適用於中等資訊區塊，寬度佔比約 17%；3 欄便當盒適用於標準內容區塊，寬度佔比約 25%；4 欄便當盒適用於寬幅內容區塊，寬度佔比約 33%；6 欄便當盒適用於雙欄佈局，寬度佔比約 50%；12 欄便當盒適用於全寬內容區塊。

### 3.3 間距系統

本系統採用 8px 作為基礎間距單位（spacing unit），所有間距值均為 8 的倍數。此設計決策基於以下考量：8 是 2 的三次方，在各種裝置上都能保持良好的一致性；8px 的間距足以創造視覺分隔，同時不會過於稀疏；8 的倍數便於計算與記憶。

標準間距值的對應關係如下：4px 用於緊密相關元素間的微調；8px 用於便當盒內部元素的標準間距；16px 用於便當盒內部群組間的間距；24px 用於便當盒之間的標準間距；32px 用於主要區塊間的強調間距；48px 用於大區塊間的顯著分隔；64px 用於頁面主要區塊間的強調分隔。

在 CSS 中，間距系統可透過 Tailwind CSS 的 spacing 工具類別或自定義 CSS 變數實現。建議建立全局 CSS 變數 `--esg-spacing-unit: 8px`，並依此計算所有間距值，確保系統的一致性與可維護性。

### 3.4 字體家族

本系統的字體家族採用系統字體優先策略，優先使用使用者裝置上安裝的高品質字體，以獲得最佳的可讀性與載入效能。針對不同語言設定不同的備援字體堆疊，確保各種語言環境下都能獲得良好的閱讀體驗。

繁體中文環境的字體堆疊為「Noto Sans TC, Noto Sans SC, Microsoft JhengHei, PingFang TC, sans-serif」。英文環境的字體堆疊為「Inter, -apple-system, BlinkMacSystemFont, Segoe UI, Roboto, sans-serif」。日文環境的字體堆疊為「Noto Sans JP, Hiragino Kaku Gothic Pro, Meiryo, sans-serif」。韓文環境的字體堆疊為「Noto Sans KR, Nanum Gothic, Malgun Gothic, sans-serif」。

若需要使用特定字體以確保品牌一致性，可考慮引入「Noto Sans」系列字體作為全系統統一字體。Noto Sans 是 Google 與 Adobe 合作開發的開源字體，支援全球大多數語言，且提供從 Thin 到 Black 七種字重，能滿足各種設計需求。

### 3.5 字級系統

本系統採用 12px 作為基礎字級（base font size），依據 1.25 的比例倍率（type scale）遞增形成完整的字級系統。此比例屬於「Minor Third」等級，產生的字級差異適中，既能建立清晰的視覺層級，又不會過於誇張。

| 字級名稱 | 像素值 | Rem 值 | 行高 | 用途說明 |
|----------|--------|--------|------|----------|
| Display | 48px | 4rem | 1.2 | 頁面大標題、英雄區塊標題 |
| H1 | 36px | 3rem | 1.25 | 頁面主標題 |
| H2 | 28px | 2.25rem | 1.3 | 區塊標題、卡片標題 |
| H3 | 22px | 1.75rem | 1.35 | 次區塊標題 |
| H4 | 18px | 1.5rem | 1.4 | 小節標題 |
| Body Large | 18px | 1.5rem | 1.6 | 重要內文、強調文字 |
| Body | 16px | 1.25rem | 1.6 | 標準內文 |
| Body Small | 14px | 1.125rem | 1.5 | 輔助說明、標籤 |
| Caption | 12px | 1rem | 1.4 | 註解、圖說 |
| Overline | 10px | 0.875rem | 1.4 | 上標文字、按鈕標籤 |

行高（line-height）的設定根據文字長度調整：短文字（如標題）的行高可設定為 1.2 到 1.4；標準內文的行高應設定為 1.5 到 1.6，以確保閱讀舒適度；長篇文章的行高可增加至 1.7 到 1.8，提升長文閱讀體驗。

### 3.6 字重規範

本系統使用七種字重（Font Weight），從 100（Thin）到 900（Black），但實際設計中主要使用四種常用字重。

| 字重名稱 | 數值 | 用途說明 |
|----------|------|----------|
| Light | 300 | 標題裝飾性使用 |
| Regular | 400 | 標準內文 |
| Medium | 500 | 強調文字、標籤 |
| Semi-Bold | 600 | 按鈕文字、小標題 |
| Bold | 700 | 標題、強調 |

字重的使用應遵循「少即是多」的原則，避免在同一頁面中使用過多種字重造成視覺混亂。建議每個頁面最多使用三到四種字重，並保持一致的使用模式。

## 四、組件設計規範

### 4.1 按鈕組件

按鈕是使用者與系統互動的核心觸點，本系統定義四種按鈕類型以滿足不同使用情境。

**Primary Button（主要按鈕）**用於主要操作動作，例如提交表單、開始流程、確認購買等。使用 Primary 主色系（#63A2B0）作為背景色，白色文字。預設狀態為實心背景，圓角 8px，右側可選放置圖示。Hover 狀態使用 Primary 400（#7FB5C4）作為背景色加深效果。Active 狀態使用 Primary 600（#548399）作為背景色。Disabled 狀態使用 Primary 100（#E5F4F8）背景色與 Neutral 400（#BDBDBD）文字色，取消 hover 與 active 效果。最小寬度為 120px，高度為 48px，內部左右 padding 為 24px。

**Secondary Button（次要按鈕）**用於次要操作動作，例如取消、返回、上一步等。使用透明背景與 Primary 邊框，Primary 文字色。Hover 狀態使用 Primary 100（#E5F4F8）背景色。Active 狀態使用 Primary 200（C2E1EB）背景色。尺寸規格與主要按鈕相同。

**Text Button（文字按鈕）**用於低優先級操作或連結型動作，例如「了解更多」、「查看全部」等。無背景、無邊框，只有文字顏色。Hover 狀態添加 Primary 100（#E5F4F8）背景色。文字大小比標準內文小一級（14px），高度為 36px。

**Icon Button（圖示按鈕）**用於純圖示操作或空間受限的情況。圓形或方形背景，尺寸為 40px × 40px 或 48px × 48px。Hover 狀態使用 Primary 100（#E5F4F8）背景色。圖示尺寸為 20px 或 24px，使用與周圍文字相同的顏色。

### 4.2 表單元件組件

表單是知識收集與用戶註冊的核心功能區域，本系統定義完整的表單元件規範。

**Input Field（輸入欄位）**用於單行文字輸入。標準高度為 48px，圓角 8px，邊框使用 Neutral 300（#E0E0E0）。Focus 狀態邊框變為 Primary 500（#63A2B0），同時顯示外光暈效果。Placeholder 文字使用 Neutral 400（#BDBDBD）。輸入文字使用 Neutral 900（#212121）。底部可選顯示 Helper Text 或 Error Message，字級為 Caption（12px）。

**Select（下拉選單）**的設計與 Input Field 保持一致，右側放置下拉箭頭圖示。選項列表使用下拉面板呈現，最大高度為 256px，選中項目使用 Primary 100（#E5F4F8）背景色標記。支援鍵盤導航與搜尋過濾功能。

**Checkbox（核取方塊）**尺寸為 20px × 20px，未選中狀態顯示 Neutral 300 邊框與透明背景。選中狀態顯示 Primary 500 背景與白色勾選圖示。Label 文字置於右側，與核取方塊保持 8px 間距。支援 indeterminate 狀態顯示半選中圖示。

**Toggle（開關）**用於二元開關設定。未開啟狀態顯示 Neutral 300 軌道與白色圓鈕。開啟狀態顯示 Primary 500 軌道與白色圓鈕向右移動。圓鈕尺寸為 20px，軌道高度為 12px，寬度為 44px。Transition 動畫時間為 200ms，使用 ease-out 緩動函數。

### 4.3 卡片組件

卡片是便當盒式佈局的核心載體，本系統定義三種卡片類型。

**Standard Card（標準卡片）**用於一般資訊展示。背景色為白色（#FFFFFF）或 Neutral 50（#FAFAFA），圓角 12px，輕微陰影效果（elevation 1）。卡片標題使用 H3（22px）字級，內文使用 Body（16px）字級。卡片可選 Header、Content、Footer 三個區域。Header 區域包含標題與可選的右側操作區；Content 區域為主要資訊展示；Footer 區域包含輔助資訊與操作按鈕。

**Interactive Card（互動卡片）**用於可點擊的功能入口。Hover 狀態提升陰影效果（elevation 2），同時可能顯示邊框變化或背景色變化。Active 狀態按下陰影效果（elevation 1）。卡片可包含圖示、標題、敘述與輔助標籤。建議在卡片右下角添加箭頭圖示提示可點擊。

**Data Card（數據卡片）**用於展示關鍵指標或統計數據。背景使用 Primary 100（#E5F4F8）或對應的 ESG 狀態色彩。數據值使用 Display（48px）或 H1（36px）字級，明顯大於標籤文字。數據變化趨勢使用功能性色彩標記，綠色代表成長、紅色代表下降。

### 4.4 導航元件組件

導航系統是使用者瀏覽系統的核心途徑，本系統定義三種導航元件。

**Top Navigation Bar（頂部導航欄）**固定於頁面頂部，高度為 64px，背景色為白色或 Primary 900（#2D4F5E）。左側放置 Logo 與品牌名稱，右側放置功能選單與使用者資訊。下邊框使用 Neutral 200（#EEEEEE）分隔。

**Side Navigation（側邊導航）**用於深層級頁面的輔助導航。寬度為 240px 或 280px，可收合至 64px。選中項目使用 Primary 100（#E5F4F8）背景色與 Primary 500（#63A2B0）文字色。未選中項目使用 Neutral 700（#616161）文字色。支援巢狀選單與圖示顯示。

**Breadcrumb（麵包屑導航）**用於顯示當前頁面位置。字級為 Body Small（14px），使用 Neutral 600（#757575）作為非當前層級顏色，當前層級使用 Neutral 900（#212121）。層級之間使用「/」或「>」分隔符號。

### 4.5 表格組件

表格用於結構化數據展示，本系統定義標準表格規範。

標準表格的標題列背景為 Neutral 100（#F5F5F5），使用 Semi-Bold（600）字重。資料列交替使用白色與 Neutral 50（#FAFAFA）背景。邊框使用 Neutral 200（#EEEEEE），僅顯示水平分隔線。儲存格內 padding 為 12px 水平、16px 垂直。文字對齊：文字左對齊、數字右對齊、狀態置中。

表格支援排序功能，點擊標題顯示排序圖示。支援固定標題列與固定第一欄功能。支援斑馬紋與高亮行功能。響應式模式下可選擇轉換為卡片堆疊式佈局。

### 4.6 圖表組件

圖表是 ESG 數據視覺化的核心工具，本系統定義圖表設計規範。

圖表色彩使用 Primary 色系與 ESG 狀態色彩，避免使用過於鮮豔的顏色。圖例位置統一為圖表右側或底部。座標軸線使用 Neutral 300（#E0E0E0），標籤文字使用 Neutral 700（#616161）。網格線使用 Neutral 100（#F5F5F5），保持輕微以不搶視覺焦點。

支援互動 tooltip 顯示詳細數據。支援圖例點擊隱藏/顯示特定數據系列。響應式模式下自動調整圖表尺寸。動畫時間設定為 300ms，使用 ease-out 緩動函數。

## 五、響應式設計

### 5.1 斷點定義

本系統採用六個響應式斷點，定義如下。

| 斷點名稱 | 最小寬度 | 最大寬度 | 容器最大寬度 | 典型裝置 |
|----------|----------|----------|--------------|----------|
| xs | 0px | 599px | 100% | 手機直立 |
| sm | 600px | 899px | 600px + 16px × 2 | 手機橫向 |
| md | 900px | 1199px | 864px + 24px × 2 | 平板直立 |
| lg | 1200px | 1439px | 1152px + 24px × 2 | 平板橫向、筆電 |
| xl | 1440px | 1919px | 1384px + 24px × 2 | 桌上型電腦 |
| xxl | 1920px | 無上限 | 1600px + 24px × 2 | 大螢幕 |

容器最大寬度的計算方式為斷點最大寬度減去左右內邊距（16px、24px、24px）。此設計確保內容在各種螢幕尺寸下都有良好的閱讀體驗，避免過寬的文字行影響閱讀舒適度。

### 5.2 行動優先策略

本系統採用「行動優先」（Mobile First）的響應式設計策略，首先為最小螢幕（xs）設計布局與樣式，然後依序為較大斷點添加样式調整。此策略的好處在於：確保核心功能在所有裝置上都能正常使用；減少樣式碼量，提高載入效能；自然地為行動裝置提供最佳體驗。

在實作上，使用 min-width 媒體查詢從小到大添加樣式。基礎樣式適用於 xs 斷點，然後使用 `@media (min-width: 600px)` 為 sm 斷點添加樣式，依此類推。避免使用 max-width 媒體查詢，以減少樣式衝突的可能性。

### 5.3 便當盒佈局的響應式規則

便當盒在不同斷點下的寬度佔比規則如下。

在 xs 斷點（手機直立）下，所有便當盒預設為全寬（100%），每行顯示 1 個便當盒。特殊情況下可使用半寬（50%）顯示 2 個便當盒，但需確保足夠的觸控空間。

在 sm 斷點（手機橫向）下，便當盒預設為半寬（50%），每行顯示 2 個便當盒。重要便當盒可使用全寬。

在 md 斷點（平板直立）下，便當盒預設為 33.33% 寬度，每行顯示 3 個便當盒。2 欄佈局（66.67% + 33.33%）可用於特殊情境。

在 lg 斷點（平板橫向、筆電）下，便當盒預設為 25% 寬度，每行顯示 4 個便當盒。3 欄佈局（50% + 25% + 25%）可用於特殊情境。

在 xl 斷點（桌上型電腦）下，便當盒預設為 25% 寬度，支援 3 欄與 4 欄混合佈局。

在 xxl 斷點（大螢幕）下，便當盒預設為 20% 寬度，支援 4 欄與 5 欄混合佈局。容器最大寬度限制為 1600px。

### 5.4 導航系統的響應式調整

導航系統在不同斷點下的呈現方式如下。

在 xs 與 sm 斷點下，頂部導航欄收合為漢堡選單，展開為全寬側邊抽屜。抽屜寬度為 280px 或 100% 螢幕寬度。Logo 顯示簡化版本。搜尋框收合為圖示按鈕。

在 md 與 lg 斷點下，頂部導航欄展開所有主要項目。Logo 顯示完整版本。搜尋框展開為輸入欄位。側邊導航可選擇性顯示為頂部標籤欄。

在 xl 與 xxl 斷點下，頂部導航欄完整展開所有項目。支援顯示更多操作項目。側邊導航預設展開，可設定預設收合。

### 5.5 觸控最佳實踐

為確保行動裝置上的良好操作體驗，本系統遵循以下觸控最佳實踐。

所有可互動元素的最小觸控區域為 44px × 44px，符合 Apple 的人機介面指南建議。若視覺元素小於此尺寸，應使用 padding 或透明的擴大區域補足。相鄰的可互動元素之間應保持至少 8px 的間隔，避免誤觸。

手勢操作方面，支援滑動（Swipe）用於頁面切換與列表瀏覽。支援長按（Long Press）用於顯示上下文選單。支援捏合縮放（Pinch）用於圖片與地圖縮放。避免使用複雜的多指手勢，確保操作直覺性。

### 6.2 翻譯管理

翻譯資源使用 JSON 格式管理，建立獨立的翻譯檔案，透過語言代碼作為鍵值索引。每個頁面或功能模組應建立對應的翻譯群組，避免單一檔案過於龐大。翻譯文字應保持簡潔，避免過長的句子影響排版。

翻譯文字的變數替換機制應支援複數形式、性别區分等複雜語法需求。日期、時間、數字的格式化應根據語言設定自動調整。貨幣與百分比格式應符合各語言的地區慣例。

### 6.3 RTL 方向翻轉

雖然目前主要語言均為 LTR（由左至右），系統已預留 RTL（由右至左）方向的支援機制。當語言切換為 RTL 時，系統應自動翻轉以下元素：文字對齊方向由左變右；圖示方向（如箭頭）應水平翻轉；表格的欄位順序應翻轉；導航選單的展開方向應翻轉；表單的標籤位置應調整。

RTL 支援的實作應使用 CSS logical properties（例如 `margin-inline-start` 而非 `margin-left`），確保樣式能夠自動適應文字方向。

### 6.4 字元限制與文字截斷

不同語言的文字長度差異可能影響佈局穩定性，本系統定義文字截斷規範。

標題文字的最大行數為 2 行，超過部分使用單行省略號（...）截斷。內文文字的最大行數為 3 行，超過部分使用多行省略號截斷。按鈕文字若過長，優先保留前 12 個中文字元或 24 個英文字元。標籤文字若過長，優先保留前 8 個中文字元或 16 個英文字元。

翻譯文字長度參考係數如下：繁體中文與簡體中文為基準值 1.0；英文為 1.5 到 2.0 倍；日文為 0.8 到 1.0 倍；韓文為 0.9 到 1.1 倍。設計時應預留足夠的文字擴展空間。

### 6.5 字體與閱讀方向

各語言的字體選擇與閱讀方向應遵循以下規範。

繁體中文使用 Noto Sans TC 或 Microsoft JhengHei，閱讀方向為 LTR，標準書寫方向為水平由左至右。簡體中文使用 Noto Sans SC 或 Microsoft YaHei，閱讀方向為 LTR，標準書寫方向為水平由左至右。英文使用 Inter 或 Roboto，閱讀方向為 LTR，標準書寫方向為水平由左至右。日文使用 Noto Sans JP 或 Hiragino Kaku Gothic Pro，閱讀方向為 LTR，標準書寫方向為水平由左至右。

## 七、動畫規範

### 7.1 動效原則

本系統的動畫設計遵循三大原則。

第一是「有意義的動效」，每個動畫都應該有明確的目的，而非純粹的裝飾。可能的目的包括：提供操作回饋（按鈕點擊後的視覺回應）；引導注意力（새로운內容出現時的動畫引導）；建立空間感（頁面切換時的轉場動畫）；傳達狀態變化（載入、完成、錯誤等狀態的可視化）。避免使用純粹裝飾性的動畫，以免分散使用者注意力或造成視覺疲勞。

第二是「一致的動效語言」，整個系統使用相同的動效風格，包括緩動函數、動畫時間、動畫曲線等。使用標準化的動效組件，確保相似操作在不同情境下有相似的動畫效果。

第三是「尊重使用者偏好」，某些使用者可能對動畫敏感，應提供減少動畫的偏好設定。當使用者設定減少動畫偏好時，系統應自動降低或禁用非必要的動畫效果。

### 7.2 緩動函數

本系統定義三種標準緩動函數用於不同類型的動畫。

**Ease Out**（cubic-bezier(0.4, 0, 0.2, 1)）用於元素進入視圖的動畫，如淡入、滑入、放大出現等。此緩動函數讓動畫開始時較快，結束時逐漸放慢，給人自然的感覺。

**Ease In**（cubic-bezier(0.4, 0, 1, 1)）用於元素離開視圖的動畫，如淡出、滑出、縮小消失等。此緩動函數讓動畫開始時較慢，結束時快速完成。

**Ease In Out**（cubic-bezier(0.4, 0, 0.2, 1)）用於元素在視圖內移動的動畫，如展開收合、選單開關等。此緩動函數讓動畫開始和結束時都較慢，中間較快，給人流暢的感覺。

**Linear**（0, 0, 1, 1）用於進度指示器、載入動畫等需要均速運動的場景。

### 7.3 動畫持續時間

動畫持續時間根據動畫類型與元素大小調整。

微互動動畫（如按鈕 hover、focus 狀態）持續時間為 150ms 到 200ms，用於極小的視覺變化。標準動畫（如展開收合、淡入淡出）持續時間為 250ms 到 300ms，用於常見的 UI 變化。複雜動畫（如頁面轉場、列表重新排序）持續時間為 350ms 到 500ms，用於較大的空間變化。大型動畫（如全頁面載入、複雜交互动畫）持續時間為 500ms 到 700ms，用於需要強調的視覺效果。

動畫持續時間應隨元素尺寸增加而適當延長，但最長不應超過 700ms，否則會讓使用者感到遲滯。

### 7.4 減少動畫偏好

系統應檢測使用者的減少動畫偏好設定，並據此調整動畫行為。

在作業系統層面，macOS 與 iOS 使用「減少動畫」設定，Windows 與 Android 使用「減少動畫」或「透明與動畫」設定。檢測方式為 CSS 媒體查詢 `@media (prefers-reduced-motion: reduce)`，若為 true則減少或禁用動畫。

減少動畫模式下的替代方案包括：使用淡入淡出代替移動；使用立即狀態切換代替漸變；保留載入進度指示器的動畫以提供狀態回饋；禁用純裝飾性動畫但保留功能性動畫。

## 八、無障礙規範

### 8.1 WCAG 2.1 AA 級標準

本系統遵循 WCAG 2.1 AA 級標準作為無障礙設計的基準要求，確保身心障礙使用者能夠正常存取與使用系統功能。

色彩對比度要求所有文字與背景的對比度至少達到 4.5:1（正常文字）或 3:1（大文字，18px 以上或 14px 粗體）。重要資訊不應僅依賴色彩區分，應同時使用形狀、圖示、文字等視覺線索。互動元素的 focus 狀態應有明顯的視覺指示。

鍵盤可存取性要求所有功能都應可透過鍵盤操作。Focus 順序應符合邏輯閱讀順序。Focus 指示器應清晰可見，不應被樣式移除。支援標準鍵盤操作（Tab、Enter、Space、方向鍵等）。

螢幕閱讀器支援要求所有圖片與非文字內容提供替代文字。表單輸入欄位應與標籤正確關聯。動態內容更新應使用 ARIA Live Regions 通知螢幕閱讀器。自定義組件應正確實作 ARIA Roles 與 Properties。

### 8.2 視覺無障礙

色彩設計方面，Primary 色系（#63A2B0）與 Neutral 900（#212121）的對比度約為 6.8:1，符合 AA 級標準。Primary 色系（#63A2B0）與白色背景的對比度約為 3.2:1，符合大文字標準但略低於正常文字標準，因此 Primary 色只用於深色文字上方。

功能性色彩（成功、警告、錯誤、資訊）都應搭配圖示或文字標籤使用，不應僅依賴色彩傳達資訊。提供高對比度模式選項，切換為更強烈的色彩對比。

### 8.3 鍵盤無障礙

Focus 指示器的設計使用 Primary 500（#63A2B0）或 Primary 700（#477385）作為 focus 邊框色，邊框寬度為 2px 到 3px。若使用 outline 樣式，應確保足夠的視覺區別性。Focus 指示器不應被 CSS 樣式移除，若有特殊需求應提供替代方案。

跳過連結（Skip Link）應為鍵盤使用者提供跳過導航直接進入主要內容的選項。跳過連結預設隱藏，鍵盤 focus 時顯示。

鍵盤快捷鍵方面，若系統提供鍵盤快捷鍵，應提供列表供使用者參考。快捷鍵組合應避免與螢幕閱讀器或瀏覽器的快捷鍵衝突。

### 8.4 螢幕閱讀器無障礙

圖片替代文字的撰寫原則如下：裝飾性圖片使用 `alt=""`（空屬性）；功能性圖片（如按鈕圖示）應說明功能而非描述外觀；內容圖片應提供有意義的描述。

表單無障礙設計要求每個輸入欄位都應有對應的 `<label>` 元素，使用 `for` 屬性與輸入欄位的 `id` 關聯。若標籤在視覺上隱藏，應使用 `.sr-only` 類別使其對螢幕閱讀器可存取。必填欄位應使用 `aria-required="true"` 標記。驗證錯誤應使用 `aria-invalid="true"` 標記，並透過 `aria-describedby` 關聯錯誤訊息。

自定義組件應正確實作 ARIA Roles：按鈕使用 `role="button"`；對話框使用 `role="dialog"`；提示訊息使用 `role="alert"` 或 `role="status"`；選單使用 `role="menu"` 與相關子角色。

### 8.5 認知無障礙

為降低認知負擔，系統設計應遵循以下原則。

語言使用方面，文字應使用簡單、清晰的語言。避免使用艱深的專業術語，若必須使用應提供解釋。說明文字應簡潔明瞭，避免冗長的段落。

一致性的設計方面，相似功能使用相似的視覺呈現與操作方式。導航結構在不同頁面間保持一致。錯誤訊息應提供明確的說明與解決建議。

提供充足的操作時間，對於有時間限制的操作應提供延長選項。支援操作確認，避免誤觸導致的不可逆操作。提供復原（Undo）機制，讓使用者能夠撤銷錯誤操作。

## 九、設計系統維護

### 9.1 版本管理

設計系統應採用語義化版本號（Semantic Versioning），版本號格式為「主版本.次版本.修訂版本」。主版本變更表示有重大結構性調整或破壞性變更。次版本變更表示新增功能且向後相容。修訂版本變更表示錯誤修復或小幅調整且向後相容。

每次版本變更都應記錄於 CHANGELOG 檔案，包含變更日期、變更類型、變更說明與相關 issue 或 pull request 連結。

### 9.2 設計資源

設計系統應提供以下設計資源供設計師與開發者使用。

圖示資源應提供 SVG 格式的完整圖示庫，包含各圖示的 24px 與 16px 版本。圖示應使用 `currentColor` 設定顏色，以便透過 CSS 控制。提供 React 與 Vue 的圖示組件封裝。

設計稿應提供 Figma 或 Sketch 格式的設計檔案，包含完整組件庫與設計變體。設計稿應與開發實作保持同步，定期更新以反映最新變更。

### 9.3 實作指南

開發者應遵循以下實作指南確保設計系統的一致性。

全局樣式應引入設計系統的 CSS 變數定義，確保所有樣式使用統一的設計 token。組件應使用設計系統提供的基礎組件進行組合，而非直接使用底層 HTML 元素。客製化應透過覆寫 CSS 變數實現，而非直接修改組件樣式，以確保未來更新時的相容性。
