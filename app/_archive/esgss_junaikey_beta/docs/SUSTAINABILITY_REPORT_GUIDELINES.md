## 十一、儀表板數據轉化為報告書依據原則

### 11.1 數據源頭追溯機制

儀表板數據需通過以下流程成為報告書有效依據：

```
┌─────────────────────────────────────────────────────────────────┐
│                    儀表板數據 → 報告書依據流程                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1️⃣ 儀表板數據採集                                               │
│     ├── 即時監看 ESG 影響力係數 (Dynamic Latency)                 │
│     ├── 交互式資產熱點圖數據                                      │
│     └── 宮格系統 (Dashboard Grid) 指標聚合                        │
│          ↓                                                        │
│  2️⃣ 數據驗證閘口 (5T Logic Gate)                                  │
│     ├── UUID 唯一標識賦予                                        │
│     ├── 原始數據哈希計算                                          │
│     └── 來源可信度評估                                            │
│          ↓                                                        │
│  3️⃣ 結構化萃取                                                   │
│     ├── 指標分類 (E/S/G/供應鏈)                                   │
│     ├── 時序標記 (年度/季度/月度)                                  │
│     └── 計算邏輯元數據附加                                         │
│          ↓                                                        │
│  4️⃣ 報告書映射                                                   │
│     ├── GRI/SASB/TCFD 指標對齊                                    │
│     ├── 敘事自動生成                                              │
│     └── 數據來源註記                                               │
│          ↓                                                        │
│  5️⃣ 誠信刻印                                                     │
│     ├── SHA-256 哈希鎖定                                          │
│     ├── IPFS CID 錨定                                             │
│     └── ZKP 驗證證明生成                                          │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 11.2 宮格系統 (Dashboard Grid) 數據接入

| 宮格類型 | 數據內容 | 報告書映射方式 |
|----------|----------|----------------|
| **碳審核宮格** | 碳排放量、範疇一/二/三 | 環境永續章節 - 溫室氣體排放 |
| **治理宮格** | 委員會組成、薪酬政策 | 公司治理章節 - 組織架構 |
| **社會宮格** | 員工福利、社會參與 | 社會責任章節 - 人才發展 |
| **財務宮格** | ESG 投資、綠色營收 | 策略分析章節 - 財務整合 |
| **風險宮格** | 氣候風險鑑別 | TCFD 章節 - 風險管理 |

### 11.3 數據可信度分級

| 等級 | 評估標準 | 報告書引用方式 |
|------|----------|----------------|
| **Lv.1** | 原始數據 + 第三方驗證 | 直接引用，可作為主要依據 |
| **Lv.2** | 原始數據 + 系統自動校準 | 直接引用，建議交叉驗證 |
| **Lv.3** | 原始數據 + AI 萃取推論 | 標註推論來源，建議補充證據 |
| **Lv.4** | 估算數據 + 模型計算 | 標註估算方法，說明不確定性 |

### 11.4 證據鏈完整性要求

每項報告書中的儀表板數據引用，需確保：

1. **源頭可查**: 可回溯至儀表板的原始數據節點
2. **計算透明**: 計算公式與參數完全公開
3. **時序正確**: 數據時間範圍與報告書期間一致
4. **版本可控**: 數據版本變更有完整紀錄
5. **簽章完整**: 經 5T 邏輯門驗證並刻印

### 11.5 自動對齊引擎

透過 **UCC Engine** 實現儀表板數據與報告書的自動對齊：

```typescript
// 數據萃取與報告書映射
interface DashboardDataPoint {
  id: string;              // UUID
  metric: string;           // 指標名稱
  value: number;           // 數值
  timestamp: Date;         // 採集時間
  sourceGrid: string;      // 來源宮格
  calculationLogic: string; // 計算公式
  esgDimension: 'E'|'S'|'G'|'SupplyChain'; // ESG 維度
  frameworkMapping: {       // 框架對應
    griCode?: string;
    sasbCode?: string;
    tcfdCode?: string;
  };
}
```
